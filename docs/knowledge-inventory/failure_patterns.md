# Failure Patterns（失败模式）

> 研究失败本身：Trigger → Wrong Assumption → Root Cause → Fix → Verification → General Lesson。
> 重点不是"怎么修"，而是"为什么当初容易犯这个错误"。

---

## Pattern FP-01 · 语义偷换（低等级证据冒充高等级结论）

- **Trigger**: 模拟器通过 → 认为 release 通过；artifact 存在 → 认为 runtime render 正确；real_execution=true → 误当 production_runtime=true。
- **Wrong Assumption**: "环境证据 ≈ 产品证据"。
- **Root Cause**: 证据等级未显式定义，等价推断被默认允许。
- **Fix**: Evidence Strength 枚举冻结 + "Emulator PASS ≠ release gate PASS" + contracts minimum_required 字段（RUN-013）。
- **Verification**: contracts evidence_strength 落地 + contract-sync status=ok。
- **General Lesson**: 验证系统必须在源头定义证据等级，并显式禁止跨等级推断；语义命名（virtual vs physical）本身就是门禁的一部分。
- **Category**: Validation / Semantic

## Pattern FP-02 · 多源真相并存（三套存储）

- **Trigger**: 同一内容同时存于 SharedPreferences + JSON + .md，编辑器保存不更新文档库。
- **Wrong Assumption**: "多个存储各管一段没问题"。
- **Root Cause**: 未定义权威数据源，写入路径各自为政。
- **Fix**: ADR-0003 收敛到 .md 单一真相源 + 三层模型 + 原子写 + 幂等迁移。
- **Verification**: storage 测试 + 迁移测试。
- **General Lesson**: 新增存储/缓存前先回答"真相源是谁"；多源并存的隐性成本是"用户数据不可知"。
- **Category**: Data Architecture

## Pattern FP-03 · 功能自相矛盾（入口暴露但后端未实现）

- **Trigger**: 工具栏能插入 `*斜体*` 但解析器不识别，预览显示原始语法。
- **Wrong Assumption**: "先加按钮，解析器后补没关系"。
- **Root Cause**: UI 能力与解析能力分别演进，缺少自洽检查。
- **Fix**: 工具栏↔解析器对照审计（CRITICAL-REVIEW §3.2）+ Phase 1.5/1.6 补齐 7 类元素。
- **Verification**: 回归测试覆盖新解析能力。
- **General Lesson**: "入口可触发但内部未实现"比"功能不存在"更伤信任；交付前做功能自洽审计。
- **Category**: Product / Feature Coherence

## Pattern FP-04 · 每按键全量重算

- **Trigger**: 每个字符输入全量解析整篇文档 + 重建所有 Widget。
- **Wrong Assumption**: "重算一遍很快"（未考虑规模项）。
- **Root Cause**: 未按规模建模成本；交互热路径用了批处理式全量算法。
- **Fix**: 块级增量渲染（Phase 3 WYSIWYG 重写）。
- **Verification**: 性能测试 / 实际体验。
- **General Lesson**: 交互热路径必须增量；全量重算只用于非交互动作。与 DP-09（预算整体建模）互为表里。
- **Category**: Performance

## Pattern FP-05 · 静态/全局状态污染测试

- **Trigger**: 测试 A 触发 CJK 字体加载失败 → 30 秒内测试 B 拿不到字体；缓存 static 跨用例共享。
- **Wrong Assumption**: "static 缓存是无害的优化"。
- **Root Cause**: 全局可变状态 = 隐式测试间依赖（顺序依赖的幽灵失败）。
- **Fix**: 加 clearCache()（部分）、构造函数注入、可重置服务。
- **Verification**: 测试稳定性提升（部分修复，`_cjkFont` 仍 static 为已知债）。
- **General Lesson**: 可测性要求状态可注入/可重置；static 可变状态与测试隔离互斥。
- **Category**: Testability

## Pattern FP-06 · 静默吞异常 → 假空状态

- **Trigger**: `catch (_) {}` 吞掉 IO 错误 → UI 显示"暂无保存的文档"。
- **Wrong Assumption**: "出错时安静点对用户更好"。
- **Root Cause**: 错误与空状态未区分；异常被当作"无数据"。
- **Fix**: 显式错误态与空状态分离呈现。
- **Verification**: 文件管理 UI 错误路径测试。
- **General Lesson**: 空状态与错误状态 UI 相同 = 用户被误导；静默 catch 只在明确无害处允许。
- **Category**: Error Handling / UX

## Pattern FP-07 · 时间预算乘积陷阱

- **Trigger**: 30s/条公式 × 并发 4，整体 120s 超时 → >16 未缓存公式导出必失败。
- **Wrong Assumption**: "单条 30s 有超时保护就够了"。
- **Root Cause**: 只看单条上限，未对"单条×数量/并发"整体建模。
- **Fix**: 导出进度 + 批量预算重设计（Phase 3 后）。
- **Verification**: 导出流程优化后验证。
- **General Lesson**: 批处理的可靠性判断必须用规模公式，不能凭单条直觉。→ 与 DP-09 同源。
- **Category**: Performance / Capacity

## Pattern FP-08 · 契约自身的漂移（元验证缺失）

- **Trigger**: contract-sync 补 s0 到 5 项后 unknown_max=3 未同步 → verify 误报 fail（roundtrip 1.0 却 fail）。
- **Wrong Assumption**: "契约更新后所有引用会自动一致"。
- **Root Cause**: 契约与派生配置是两处，无自动同步校验。
- **Fix**: unknown_max 与 s0 对齐 + contract-sync 校验。
- **Verification**: RUN-009 contract-sync meta validation。
- **General Lesson**: 机器验证系统自身也要被验证（元验证层）；契约漂移是契约驱动开发的固有风险。
- **Category**: Contract-Driven Dev / Meta-validation

---

## Pattern FP-09 · 环境/产品失败混淆

- **Trigger**: wpscli 未装 → Agent 报告"Word Export broken"。
- **Wrong Assumption**: "工具链缺失 = 产品缺陷"。
- **Root Cause**: 失败分类只有"成功/失败"两态，未区分环境缺失。
- **Fix**: FFX 退出码 127（ENV_MISSING）独立。
- **Verification**: FFX 验证编排测试。
- **General Lesson**: 验证/告警系统的失败分类必须区分"环境/产品/证据不足"，否则 Agent 归因方向错。→ 与 DP-08 同源。
- **Category**: Validation / Attribution
