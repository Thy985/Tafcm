# ADR-0033: 产品定位收敛——用户侧聚焦「移动端排版创作」，Agent/CLI 降级为工程差异化

- **状态**: Proposed（Human Owner 经 issue #243 决策选定方向；PR 合并即视为 Accepted）
- **日期**: 2026-09-12
- **关联**: issue #243（F-2026-09-03-05 产品定位 B/C 分裂）· ADR-0031（rebrand Tafcm）· README「这是什么」节

## 背景

产品定位审查（F-2026-09-03-05）发现 B/C 分裂：五维定位（T/A/F/C/M）中 **A·Agent-native** 与 **C·CLI-native** 是工程侧能力（ADI 诊断接口 / ffx-cli 工具链），与「移动端 Typora 写作用户」这一 C 端核心用户群没有交集。定位含糊影响功能优先级、发布渠道与社区运营的指向；「移动端 Typora」（创作）与「任意 .md 即开即看」（查看）两个卖点并存，目标用户与使用场景不同。

## 决策

Human Owner 于 2026-09-12 经 issue #243 决策选定 **方向 3：收敛为移动端创作工具**：

1. **核心用户**：移动端学术/笔记写作用户（创作工具定位）；「便携查看器」作为 .md 单一真相源的自然副产品保留表述，不再作为并列定位。
2. **用户侧定位聚焦 T / F / M 三维**：Typeset（所见即所得排版）、Formula-aware（公式/图表）、Markdown-first（.md 即开即看）。
3. **A / C 降级为「工程差异化」**：Agent-native 与 CLI-native 不再作为用户可见卖点并列，改为 README 的「工程侧」小节表述——它们仍是项目真实能力（ADI / ffx-cli 持续演进），但不对 C 端用户承诺。
4. **北极星指标**（后续功能排序依据）：每周活跃文档数（创作粘性）；辅助指标：导出成功率（排版质量代理）、外部 .md 打开成功率（便携性代理）。

## 动机

- 定位演讲首屏一句话可说清「给谁、解决什么、为什么现在」（#243 Validation Plan 验收）。
- 与 AGENTS.md §0 产品愿景（移动端 Typora 类产品、以公式/图表/学术写作为特色）一致，改动最小、无需推翻既有工程资产。
- 避免「对 C 端用户讲 Agent 可诊断」的错位沟通。

## 后果

**正向**：

- README / 发布文案 / 后续功能规划有了统一排序依据（服务 T/F/M 的优先，A/C 相关投入转为工程内驱）。
- 「创作 vs 查看」的内在张力收敛为「创作为主、查看为其子能力」。

**负向 / 风险**：

- 开发者向传播（若未来做）需另行展开，本决策不覆盖。
- README 五维表述改为「三维 + 工程差异化」，ADR-0031 的 rebrand 叙述需以本 ADR 为准（部分 supersede）。

## 替代方案

1. **双层定位并存**（用户+开发者分层表述）——否决：首屏仍无法一句话说清，分裂照旧。
2. **暂缓决策**——否决：定位含糊持续影响 Phase 4 立项排序，审查方（Doubao Supervisor）建议尽快收敛。
3. **转向查看器利基**（放弃创作主线）——否决：与既有 WYSIWYG 工程资产（Phase 3 全部投入）不匹配。

## 边界

- 本 ADR 只收敛**表述与排序依据**，不删减任何工程能力（ADI / ffx-cli 不受影响）。
- 同步/跨设备方向（#244）依赖本决策的核心用户定义，另立决策。
